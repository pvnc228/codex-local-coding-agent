# Project brief

## Название

Local Coding Agent

## Проблема

Небольшие исправления часто не требуют полного контекста большой модели. Для них выгодно делегировать исполнение локальной модели, оставляя у основного агента контроль границ, безопасности и качества результата.

## Цель

Создать маленький внешний контроллер, который безопасно делегирует атомарные coding-задачи локальным моделям Ollama и возвращает проверяемый результат.

## Не цели MVP

- автономная разработка большой функции;
- самостоятельное изменение всего репозитория;
- постоянная память локальной модели;
- произвольный shell-доступ;
- автоматический push, commit или публикация;
- замена ревью человеком или Codex.

## Единица работы

Одна задача должна иметь:

- идентификатор;
- цель в одном предложении;
- список разрешённых файлов;
- компактный контекст;
- ограничения;
- команду targeted-проверки;
- критерии приёмки.

Пример:

~~~yaml
id: unique-preserve-order
goal: убрать сортировку из unique и сохранить порядок первого появления
files:
  - src/unique.ts
checks:
  - npm test -- unique
constraints:
  - не менять публичную сигнатуру
  - не добавлять зависимости
acceptance:
  - diff изменяет только src/unique.ts
  - сортировка удалена
  - targeted test passed
~~~

## Критерии успеха MVP

1. Запросы всегда отправляются в UTF-8.
2. Контекст ограничен allowlist-файлами и лимитом токенов.
3. Модель не может произвольно выполнять команды.
4. Любой патч проверяется до применения.
5. Результат теста подтверждается внешним runner-ом.
6. Tool-loop завершается по ограничению ходов или финальному ответу.
7. Повторный одинаковый tool call останавливает цикл и переводит задачу в 'failed'.
8. Все входы, calls, diff и checks журналируются.
9. Ошибки схемы, синтаксиса и diff переводятся в детерминированные точечные предписания (Pinpointed Prescriptions Engine) для надежного самоисправления малых моделей.
10. 100% CLI Parity & Agent-Agnostic Architecture: любая функциональность системы полностью доступна и контролируема из консоли через подкоманды CLI (`delegate`, `decompose`, `profiles`, `memory`, `calibrate`, `benchmark`, `apply`, `init-skill`, `doctor`, `init-mcp`, `test-run`, `serve-mcp`, `monitor`) с поддержкой `--json` и снабжена Agent Skill.



## Текущая гипотеза

Для локальной модели лучше всего работает:

- 'think: false' по умолчанию;
- 'temperature: 0';
- 'num_ctx: 4096..8192' для малых задач;
- 'num_predict: 256..512';
- 'format: json' или JSON Schema;
- один узкий tool за шаг;
- короткий русский или английский system contract;
- внешний diff validator и max-turn guard;
- точечные детерминированные рецепты исправления ошибок (zero distillation).
