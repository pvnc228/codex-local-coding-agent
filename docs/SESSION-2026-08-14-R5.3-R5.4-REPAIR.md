# Сессия 2026-08-14 — repair gate R5.3/R5.4

## Причина работы

Повторный review пометил предыдущую реализацию R5.3/R5.4 как `REQUEST CHANGES`. P0 не было, но несколько P1/P2 нарушали контракт: Tasks выдавал внутренний словарь вместо `CallToolResult`, неизвестный `taskId` маскировался как failed task, `apply` допускал пустой список checks, подтверждение не показывало identity предложения, async MCP handlers блокировали event loop, а bounded `TaskBudget` не был обязательным на всех публичных входах.

## Что изменено

- `local_coding_agent/tasks.py`: terminal task теперь возвращает wire-shape `CallToolResult` (`content`, `isError`, `structuredContent`); controller failure остаётся task со статусом `completed` и `isError: true`; неизвестные `get/update/cancel` получают JSON-RPC `-32602`.
- `local_coding_agent/service.py` и `controller.py`: `TaskBudget` стал обязательным default preflight на public service/controller seams; custom budget передаётся дальше в controller/tool allowlist. Non-empty apply требует хотя бы один targeted check.
- `local_coding_agent/mcp_server.py`: перед `apply_proposal` строится bounded preview с proposal id, workspace, summary, files и diff; `delegate_code` и `apply_proposal` выносят blocking service calls из event loop через `asyncio.to_thread`.
- `local_coding_agent/controller.py`: checks/evidence в результате принадлежат внешнему runner-у; rollback failure помечает `workspace_modified=true` и добавляет риск.
- `local_coding_agent/validators.py`: SEARCH/REPLACE корректно сохраняет/создаёт final-newline marker.
- `local_coding_agent/repository_tools.py`: stdout/stderr дочернего test process непрерывно дренируются bounded collectors без временных файлов, pipe deadlock и неограниченного диска.
- `local_coding_agent/calibration.py` и CLI: модель считается загруженной один раз, другие loaded models учитываются, а число workers требует явной оценки per-worker context/KV; `/api/tags` помечается только диагностическим источником.
- `pyproject.toml`: optional MCP dependency закреплена на `mcp==2.0.0`.
- README, Architecture, Protocol, MCP design, Handoff и Roadmap синхронизированы с фактическим контрактом; live Ollama claims не расширены.

Regression tests отдельно покрывают Tasks wire result, unknown IDs, informed confirmation, async offload, mandatory checks, external evidence, rollback flag, bounded pipes, calibration и final newline.

## Границы evidence

В этой сессии не запускались Ollama live benchmark, реальная модель, live apply на настоящей модели или durable reconnect после перезапуска процесса. Поэтому R7/R8 и runtime/model quality не объявляются заново live-проверенными; следующим gate остаётся внешний runtime oracle.

Эта работа занесена в [ROADMAP.md](ROADMAP.md) как отдельный repair gate R5.3/R5.4.

## Дополнительный self-review hardening — 2026-08-14

После первого repair gate выполнена отдельная самопроверка по `code-review-expert`. Она не нашла P0, но выявила четыре конкретных края, которые нельзя было оставлять закрытыми только предыдущим `170/170`:

- resolver подтверждения проглатывал ошибку preview и оставлял возможность применить patch по пустому/unknown preview;
- sync MCP path обходил `BoundedWorkerPool` для клиентов без Tasks capability и имел только неограниченную очередь default executor;
- параллельные `apply` могли перемешать check/apply/post-check/rollback одной workspace;
- `calibrate_for_model` валидировал часть параметров после source shortcut и читал `/api/ps` дважды.

В этом проходе:

- `ApplyConfirmation` получил `proposal_id`, `workspace_ref` и SHA-256 digest канонического preview; resolver fail-closed, а handler повторно сверяет preview перед `service.apply`;
- для sync `delegate_code` и `apply_proposal` добавлен bounded admission gate с `max_workers + max_queue` и явным `queue_overload`;
- `DelegationService` получил per-workspace `RLock`, охватывающий всю mutation pipeline от `check_patch_applies` до rollback;
- calibration валидирует `vram_budget_bytes`, `hard_max` и `per_worker_context_bytes` до shortcut, переиспользует один loaded snapshot; недостижимая ветка `failed` в Tasks удалена;
- добавлены regression tests на wrong digest, недоступный preview, queue overload, сериализацию apply, invalid calibration inputs и single-snapshot consistency.

Проверки после изменений:

